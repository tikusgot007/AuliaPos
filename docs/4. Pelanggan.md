| Nama Subbab        | Daftar Pelanggan                                                                                                                                                                                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Menyediakan master data pelanggan yang dapat dilihat, dicari, diedit, dan dihapus oleh user yang memiliki akses ke modul pelanggan.                                                                                                                                                             |
| Deskripsi          | `/pelanggan` mengambil seluruh data dari tabel `pelanggan` melalui `PelangganModel` dan mengurutkannya berdasarkan `nama` ASC. View menampilkan nama, nomor HP, alamat, diskon, serta aksi Edit dan Hapus. Data kemudian diperkaya dengan DataTables di browser untuk pagination dan pencarian. |
| Aturan Bisnis      | Daftar diurutkan berdasarkan nama secara ascending. Diskon pelanggan ditampilkan dalam persen; nilai `0` ditampilkan sebagai `0%`. Tidak ada status aktif/nonaktif pada model pelanggan.                                                                                                        |
| Alur               | User membuka `/pelanggan` → `Pelanggan::index()` mengambil seluruh pelanggan → data dikirim ke view → DataTables melakukan pagination dan filtering di sisi browser → user dapat memilih Tambah, Edit, atau Hapus.                                                                              |
| Hak Akses          | Route hanya mensyaratkan `auth`, sehingga **admin dan kasir yang login** dapat mengakses modul Pelanggan.                                                                                                                                                                                       |
| Kondisi & Batasan  | Seluruh data pelanggan dimuat ke halaman sebelum DataTables melakukan filtering. Pagination dan pencarian pada halaman daftar bukan server-side.                                                                                                                                                |
| Data yang Terlibat | `pelanggan.id`, `nama`, `no_hp`, `alamat`, `diskon`.                                                                                                                                                                                                                                            |
| Catatan            | Master pelanggan juga digunakan oleh POS. Relasi transaksi → pelanggan menggunakan `pelanggan_id`; foreign key pada `transaksi` menggunakan `ON DELETE SET NULL`.                                                                                                                               |
| Status             | Terimplementasi pada `v2.1`.                                                                                                                                                                                                                                                                    |

| Nama Subbab        | Tambah Pelanggan                                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Membuat data pelanggan baru yang dapat dipilih pada transaksi POS dan digunakan untuk menyimpan informasi kontak serta diskon pelanggan.                                                                                    |
| Deskripsi          | `/pelanggan/tambah` menampilkan form nama, nomor HP, alamat, dan diskon. POST `/pelanggan/simpan` melakukan validasi manual sebelum menyimpan data melalui `PelangganModel`.                                                |
| Aturan Bisnis      | Nama wajib diisi dan minimal 2 karakter. Nama pelanggan harus unik terhadap data pelanggan yang sudah ada. Nomor HP dan alamat bersifat opsional. Diskon default `0` jika tidak dikirim.                                    |
| Alur               | User membuka form → mengisi data → POST `/pelanggan/simpan` → validasi nama → pengecekan duplikat nama → `PelangganModel::save()` → berhasil kembali ke `/pelanggan`; jika gagal, kembali ke form dengan input sebelumnya.  |
| Hak Akses          | **Admin dan kasir** yang login dapat mengakses karena route menggunakan `auth` tanpa pembatasan admin-only.                                                                                                                 |
| Kondisi & Batasan  | Controller secara eksplisit memvalidasi nama dan duplikasi. Field diskon pada UI membatasi input 0–100 dengan step 1, tetapi validasi controller yang terlihat tidak melakukan pemeriksaan range tersebut sebelum `save()`. |
| Data yang Terlibat | `pelanggan.nama`, `pelanggan.no_hp`, `pelanggan.alamat`, `pelanggan.diskon`.                                                                                                                                                |
| Catatan            | Selain form master, POS memiliki endpoint `/api/tambah-pelanggan` untuk kebutuhan penambahan pelanggan dari workflow kasir.                                                                                                 |
| Status             | Terimplementasi pada `v2.1`.                                                                                                                                                                                                |

| Nama Subbab        | Edit Pelanggan                                                                                                                                                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Memperbarui data pelanggan yang sudah ada, termasuk informasi kontak dan diskon yang digunakan pada transaksi.                                                                                                                                                    |
| Deskripsi          | `/pelanggan/edit/{id}` mengambil pelanggan berdasarkan ID. Form memungkinkan perubahan nama, nomor HP, alamat, dan diskon. POST `/pelanggan/update/{id}` melakukan pengecekan keberadaan pelanggan, validasi nama, pengecekan duplikat, lalu menyimpan perubahan. |
| Aturan Bisnis      | Nama wajib dan minimal 2 karakter. Nama tidak boleh sama dengan pelanggan lain; nama milik record yang sedang diedit diperbolehkan tetap sama. Field lain dapat diperbarui.                                                                                       |
| Alur               | User memilih Edit → controller mencari pelanggan → form ditampilkan → user mengubah data → POST update → validasi → cek duplikasi nama → update database → kembali ke daftar.                                                                                     |
| Hak Akses          | **Admin dan kasir** yang login dapat mengakses.                                                                                                                                                                                                                   |
| Kondisi & Batasan  | Jika ID tidak ditemukan, user dikembalikan ke daftar dengan pesan error. Form memiliki parameter `return=kasir` yang memungkinkan workflow edit dari POS kembali ke `/kasir` dengan data pelanggan hasil edit.                                                    |
| Data yang Terlibat | `pelanggan.id`, `nama`, `no_hp`, `alamat`, `diskon`. Parameter return POS membawa `pelanggan_id`, `pelanggan_nama`, `pelanggan_telp`, dan `pelanggan_diskon`.                                                                                                     |
| Catatan            | Saat edit dipanggil dari POS, `kasir-shared.js` mengarahkan user ke `/pelanggan/edit/{id}?return=kasir`. Setelah update berhasil, controller mengembalikan user ke `/kasir` dan mengirim data pelanggan melalui query string.                                     |
| Status             | Terimplementasi pada `v2.1`.                                                                                                                                                                                                                                      |

| Nama Subbab        | Hapus Pelanggan                                                                                                                                                                                                                   |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Menghapus data pelanggan yang belum memiliki keterikatan dengan transaksi.                                                                                                                                                        |
| Deskripsi          | `/pelanggan/hapus/{id}` terlebih dahulu memeriksa apakah pelanggan pernah digunakan pada tabel transaksi. Jika sudah digunakan, penghapusan ditolak. Jika belum, record pelanggan dihapus menggunakan `PelangganModel::delete()`. |
| Aturan Bisnis      | Pelanggan yang memiliki minimal satu transaksi **tidak boleh dihapus**. Pelanggan tanpa transaksi dapat dihapus secara permanen dari tabel `pelanggan`.                                                                           |
| Alur               | User memilih Hapus → controller menghitung transaksi dengan `pelanggan_id` tersebut → jika jumlah > 0, proses dihentikan dan pesan error ditampilkan → jika tidak ada transaksi, record dihapus → kembali ke daftar pelanggan.    |
| Hak Akses          | **Admin dan kasir** yang login dapat mengakses route karena route menggunakan `auth` tanpa admin-only restriction.                                                                                                                |
| Kondisi & Batasan  | Pemeriksaan dilakukan berdasarkan seluruh transaksi yang memiliki `pelanggan_id` tersebut. Tidak ada soft delete pelanggan pada implementasi controller ini.                                                                      |
| Data yang Terlibat | `pelanggan.id`, `transaksi.pelanggan_id`.                                                                                                                                                                                         |
| Catatan            | Foreign key transaksi memang menggunakan `ON DELETE SET NULL`, tetapi controller sengaja mencegah penghapusan pelanggan yang sudah digunakan agar histori transaksi tetap memiliki referensi pelanggan.                           |
| Status             | Terimplementasi pada `v2.1`.                                                                                                                                                                                                      |

| Nama Subbab        | Pencarian Pelanggan                                                                                                                                                                                                                                                                                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Memungkinkan kasir menemukan pelanggan dengan cepat saat membuat transaksi tanpa harus membuka daftar master pelanggan.                                                                                                                                                                                                                                          |
| Deskripsi          | POS menggunakan endpoint `GET /api/search-pelanggan`. `PelangganModel::searchPelanggan()` mencari keyword pada `nama` atau `no_hp` dan membatasi hasil maksimal 10 record.                                                                                                                                                                                       |
| Aturan Bisnis      | Pencarian mulai dijalankan ketika keyword minimal 2 karakter. Hasil berasal dari pencocokan `LIKE` pada nama dan nomor HP. Jika nama yang diketik persis sama dengan salah satu hasil, POS otomatis memilih pelanggan tersebut.                                                                                                                                  |
| Alur               | Kasir mengetik nama/nomor HP → `kasir-shared.js` menunggu input → jika ≥2 karakter, request AJAX dikirim ke `/api/search-pelanggan` → controller memanggil `searchPelanggan()` → maksimal 10 hasil dikembalikan → daftar kandidat ditampilkan → kasir memilih pelanggan atau sistem memilih otomatis jika nama cocok persis.                                     |
| Hak Akses          | **Admin dan kasir** yang login. Endpoint `/api/search-pelanggan` menggunakan filter `auth`.                                                                                                                                                                                                                                                                      |
| Kondisi & Batasan  | Keyword kurang dari 2 karakter tidak dikirim ke server. Hasil dibatasi 10 record. Pencarian hanya berdasarkan `nama` dan `no_hp`, bukan alamat atau diskon. Request sebelumnya dibatalkan ketika pencarian baru dimulai untuk mencegah hasil request lama menimpa hasil terbaru.                                                                                 |
| Data yang Terlibat | `pelanggan.id`, `nama`, `no_hp`, `diskon`; keyword pencarian.                                                                                                                                                                                                                                                                                                    |
| Catatan            | Saat pelanggan dipilih, POS menyimpan objek `pelangganTerpilih` termasuk ID, nama, nomor HP, dan diskon. Diskon pelanggan kemudian dapat mengaktifkan mode **Diskon Pelanggan** pada UI. Source code juga menegaskan bahwa nilai diskon final untuk transaksi tetap di-resolve ulang di backend dari database; nilai pada JavaScript digunakan untuk UI/preview. |
| Status             | Terimplementasi pada `v2.1`.                                                                                                                                                                                                                                                                                                                                     |
