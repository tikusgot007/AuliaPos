| Deskripsi          | Modul riwayat menggunakan route `/transaksi`, yang juga merupakan daftar transaksi. Tanpa keyword, histori yang ditampilkan berasal dari database operasional sesuai rentang tanggal/filter. Dengan keyword, pencarian diperluas ke database archive melalui `TransaksiArchiveService::cariUntukDaftarTransaksi()`. Detail juga mempunyai fallback archive berdasarkan ID. |
| Aturan Bisnis      | Archive bertujuan mengurangi beban database utama tanpa kehilangan histori. Data yang di-archive tidak diubah status atau nilainya. Archive dapat dicari dan dilihat, tetapi bersifat read-only untuk workflow transaksi normal.                                                                                                                                           |
| Alur               | Buka daftar transaksi → tentukan periode/filter → query database utama → jika menggunakan keyword, query archive juga → gabungkan hasil → tandai sumber `aktif`/`archive` → tampilkan daftar → pilih detail → jika ID hanya ada di archive, controller mengambil data lengkap dari archive.                                                                                |
| Hak Akses          | Membutuhkan login untuk melihat histori. Operasi archive sendiri merupakan fungsi admin-only dan dilakukan manual melalui modul Archive Transaksi.                                                                                                                                                                                                                         |
| Kondisi & Batasan  | Tanpa keyword, transaksi archive tidak digabungkan ke daftar berdasarkan periode. Dengan keyword, histori aktif + archive dicari. Jika archive gagal diakses, daftar transaksi aktif tetap ditampilkan dan kegagalan archive dicatat di log. Transaksi archive tidak dapat dibayar, diselesaikan, dibatalkan, atau dicetak ulang melalui workflow normal.                  |
| Data yang Terlibat | Database utama `transaksi`, `detail_transaksi`, `pembayaran`; SQLite archive melalui `TransaksiArchiveService`; field penanda `_sumber`; invoice, No Order, tanggal, pelanggan, kasir, total dan status.                                                                                                                                                                   |
| Catatan            | Kebijakan archive aktif: transaksi yang sudah memenuhi cutoff archive dipindahkan secara manual setelah preview, backup, copy, dan validasi. Status/nilai transaksi tidak dimodifikasi selama proses archive. `docs/AULIA.md` merupakan sumber aturan aktif; `docs/CHANGELOG.md` menjelaskan alasan perubahan historis.                                                    |
