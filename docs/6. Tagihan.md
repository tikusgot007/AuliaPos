| Nama Subbab        | Daftar Tagihan                                                                                                                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Menampilkan seluruh transaksi yang masih memiliki sisa pembayaran dan perlu ditindaklanjuti sebagai tagihan.                                                                                                                                                                                                                    |
| Deskripsi          | Route `/tagihan` memanggil `Tagihan::index()`. Data berasal dari `transaksi` dengan join `pelanggan` dan `users`. Tagihan ditentukan berdasarkan `status_pembayaran != lunas` serta transaksi tidak berstatus `batal` atau `mangkrak`. Tanpa filter tanggal, semua tagihan yang belum lunas ditampilkan, termasuk piutang lama. |
| Aturan Bisnis      | Tagihan ditentukan oleh **status pembayaran**, bukan status pekerjaan. Transaksi `proses` maupun `selesai` dapat masuk Tagihan selama belum lunas. `batal` dan `mangkrak` dikeluarkan dari radar tagihan. Data diurutkan tanggal transaksi ASC sehingga tagihan tertua berada lebih dahulu.                                     |
| Alur               | Buka `/tagihan` → baca filter → validasi `kasir_id` → query transaksi belum lunas → exclude `batal`/`mangkrak` → hitung jatuh tempo setiap transaksi → jika filter terlambat aktif, sisakan yang overdue → render daftar.                                                                                                       |
| Hak Akses          | Membutuhkan login. Tidak dibatasi admin-only; halaman dapat digunakan oleh role login sesuai filter auth pada route.                                                                                                                                                                                                            |
| Kondisi & Batasan  | Tidak ada batas tanggal default. Filter tanggal hanya diterapkan jika dikirim. Filter `saya=1` selalu menggunakan `session id_user`, bukan ID user dari URL. Archive tidak menjadi sumber daftar Tagihan karena transaksi archive sudah tidak berada dalam radar tagihan utama.                                                 |
| Data yang Terlibat | `transaksi.id`, `kode_invoice`, `no_order`, `tanggal`, `pelanggan_id`, `kasir_id`, `grand_total`, `total_dibayar`, `status_pembayaran`, `status`; `pelanggan.nama`; `users.nama/username/inisial`; hasil kalkulasi `jatuh_tempo` dan `is_overdue`.                                                                              |
| Catatan            | `status_pembayaran` pada tabel view dihitung kembali menggunakan `KalkulasiStatusPembayaran`, sehingga tampilan mengikuti total pembayaran efektif.                                                                                                                                                                             |

| Nama Subbab        | Detail Tagihan                                                                                                                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tujuan             | Menampilkan rincian transaksi yang memiliki tagihan, termasuk item, pelanggan, total transaksi, pembayaran aktif, sisa tagihan, dan histori pembayaran.                                                                                                                                    |
| Deskripsi          | Route `/tagihan/detail/{id}` menggunakan `Tagihan::detail()`, tetapi me-render view `transaksi/detail.php`. Controller mengambil transaksi, detail item, pembayaran aktif, dan pelanggan. Flag `dariTagihan=true` membuat view menyesuaikan tombol kembali dan menyediakan aksi pelunasan. |
| Aturan Bisnis      | Total pembayaran hanya berasal dari pembayaran `aktif`. Sisa tagihan dihitung sebagai `grand_total - total_dibayar`. Pelunasan tidak mengubah status pekerjaan transaksi secara otomatis; yang berubah adalah `status_pembayaran`.                                                         |
| Alur               | Buka detail → ambil transaksi → ambil detail item → ambil pembayaran aktif → ambil pelanggan → hitung total pembayaran dan sisa → render detail → pengguna dapat membayar sekarang atau menggunakan backdate jika memiliki otoritas.                                                       |
| Hak Akses          | Membutuhkan login. Aksi pembayaran/backdate tetap divalidasi backend sesuai otoritas.                                                                                                                                                                                                      |
| Kondisi & Batasan  | Transaksi `batal` tidak dapat menerima pembayaran baru. Transaksi `mangkrak` tidak menampilkan tombol pembayaran; harus diaktifkan kembali ke `proses` terlebih dahulu. Detail Tagihan tidak memiliki fallback archive seperti `Transaksi::detail()`.                                      |
| Data yang Terlibat | `transaksi`, `detail_transaksi`, `pembayaran`, `pelanggan`, `users`; khususnya `grand_total`, `total_dibayar`, `status_pembayaran`, `status`, `tanggal`, dan histori pembayaran.                                                                                                           |
| Catatan            | View yang digunakan adalah view detail transaksi yang sama, sehingga informasi dan histori pembayaran konsisten dengan modul Transaksi.                                                                                                                                                    |

| Nama Subbab        | Pelunasan Tagihan                                                                                                                                                                                                                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tujuan             | Menerima pembayaran sebesar sisa tagihan sehingga status pembayaran transaksi berubah menjadi `lunas`.                                                                                                                                                                                                             |
| Deskripsi          | Route `POST /tagihan/lunasi/{id}` menjalankan `Tagihan::lunasi()`. Controller mengambil transaksi, memastikan belum lunas dan bukan `batal`, menghitung sisa berdasarkan pembayaran aktif, lalu memanggil `TransaksiModel::tambahPembayaran()`.                                                                    |
| Aturan Bisnis      | Pelunasan menggunakan nominal **sisa tagihan**, bukan nominal bebas. Metode harus `tunai`, `qris`, atau `transfer`. Setelah pembayaran berhasil, status pembayaran menjadi `lunas`; status transaksi tidak otomatis berubah menjadi `selesai`.                                                                     |
| Alur               | Klik Bayar → buka payment modal → pilih metode → endpoint `/tagihan/lunasi/{id}` → cek transaksi → cek bukan `batal` dan belum lunas → hitung `SUM(pembayaran aktif)` → hitung sisa → buat pembayaran sebesar sisa → `tambahPembayaran()` → sinkronkan status pembayaran → response sukses → reload daftar/detail. |
| Hak Akses          | Membutuhkan login. Backdate dan override kasir penerima tersedia untuk admin atau Effective Shift Leader. Pembayaran normal menggunakan kasir login.                                                                                                                                                               |
| Kondisi & Batasan  | Transaksi `batal` ditolak. Jika sisa `<= 0`, pelunasan ditolak karena transaksi sudah lunas. Metode pembayaran di-whitelist. Pelunasan tidak menjalankan `ubahStatus(..., selesai)`.                                                                                                                               |
| Data yang Terlibat | `transaksi.grand_total`, `transaksi.status`, `transaksi.status_pembayaran`; `pembayaran.jumlah`, `metode`, `uang_diterima`, `kembalian`, `tanggal`, `kasir_id`, `status`.                                                                                                                                          |
| Catatan            | Endpoint Tagihan menggunakan method pembayaran yang sama dengan workflow pembayaran transaksi, sehingga aturan validasi pembayaran dan backdate tetap terpusat di `TransaksiModel::tambahPembayaran()`.                                                                                                            |

| Nama Subbab        | Jatuh Tempo Tagihan                                                                                                                                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Menentukan tanggal jatuh tempo dan kondisi terlambat suatu tagihan tanpa menambah kolom baru pada database.                                                                                                                     |
| Deskripsi          | Jatuh tempo dihitung menggunakan `KalkulasiJatuhTempo`: `transaksi.tanggal + Config\Tagihan::$defaultTempoHari`. Nilai default adalah **7 hari** dan dapat di-override melalui `.env` dengan `tagihan.defaultTempoHari`.        |
| Aturan Bisnis      | Jatuh tempo adalah kebijakan global untuk seluruh transaksi/pelanggan. Tidak disimpan ke database. Tagihan dianggap terlambat apabila `jatuh_tempo < tanggal hari ini`; pada hari jatuh tempo sendiri belum dianggap terlambat. |
| Alur               | Buka `/tagihan` → baca `defaultTempoHari` → untuk setiap tagihan hitung `jatuh_tempo` → bandingkan dengan tanggal hari ini → set `is_overdue` → view memberi indikator overdue jika true.                                       |
| Hak Akses          | Mengikuti akses halaman Tagihan; tidak membutuhkan hak admin khusus.                                                                                                                                                            |
| Kondisi & Batasan  | Tidak ada tempo berbeda per pelanggan/transaksi. Mengubah konfigurasi tempo akan mengubah hasil perhitungan ketika halaman dibuka kembali karena nilai tidak dipersistenkan.                                                    |
| Data yang Terlibat | `transaksi.tanggal`, `Config\Tagihan::$defaultTempoHari`, tanggal saat ini, `KalkulasiJatuhTempo::hitung()` dan `isOverdue()`.                                                                                                  |
| Catatan            | Keputusan aktif di `docs/AULIA.md` secara eksplisit memilih kebijakan global tanpa migration/kolom jatuh tempo. Service bersifat pure/stateless agar perhitungannya dapat diuji deterministik.                                  |

| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Memberikan pengingat kepada kasir mengenai tagihan miliknya yang masih belum lunas dan masih berada dalam jendela reminder.                                                                                                                                                                   |

Sistem mencari transaksi milik user login dengan `status_pembayaran` `belum_bayar` atau `dp`, status transaksi bukan `batal`/`mangkrak`, dan tanggal transaksi masih dalam rentang tempo yang dikonfigurasi. |
| Aturan Bisnis      | Reminder hanya untuk `kasir_id = user login`. Jendela reminder menggunakan nilai `Config\Tagihan::$defaultTempoHari`, default 7 hari. Reminder tidak menggunakan polling; pengecekan dilakukan server-side ketika halaman Kasir dibuka.                                                       |
| Alur               | User membuka `/kasir` → controller memeriksa session user → cek jeda reminder 15 menit → query transaksi belum lunas milik user → jika jumlah > 0, simpan timestamp reminder → view menampilkan toast/notifikasi.                                                                             |

| Catatan            | Reminder tidak sama dengan daftar Tagihan global. Daftar Tagihan dapat menampilkan semua tagihan, sedangkan reminder hanya menyoroti tagihan milik kasir yang sedang login.                                                                                                                   |

Filter `hanya_terlambat` dilakukan di PHP sehingga semua tagihan yang masuk query harus dihitung jatuh temponya terlebih dahulu. Default halaman tidak dibatasi 7 hari; tombol **7 Hari Terakhir** hanya merupakan preset filter. |

| Catatan            | Urutan daftar server-side adalah tanggal ASC, kemudian DataTables juga mempertahankan tanggal ASC agar tagihan yang lebih lama berada di bagian atas.                                                                                                                                       |

| Nama Subbab        | Riwayat Tagihan                                                                                                                                                                                                                                                                                                                          |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tujuan             | Menyediakan konteks histori kewajiban pembayaran berdasarkan transaksi yang masih memiliki saldo, sekaligus memungkinkan penelusuran transaksi sampai detail dan histori pembayarannya.                                                                                                                                                  |
| Deskripsi          | Modul Tagihan tidak memiliki tabel/halaman riwayat terpisah. `/tagihan` merupakan daftar current receivables yang dibentuk langsung dari `transaksi` berdasarkan `status_pembayaran != lunas`, dengan transaksi `batal` dan `mangkrak` dikecualikan. Detail menggunakan `/tagihan/detail/{id}` dan menampilkan histori pembayaran aktif. |
| Aturan Bisnis      | Tagihan bukan arsip transaksi dan bukan lifecycle pekerjaan. Setelah transaksi lunas, transaksi keluar dari daftar Tagihan. Histori pembayaran tetap berada pada transaksi dan dapat dilihat melalui detail. Pembayaran yang `reversed` tidak dihitung sebagai pembayaran efektif.                                                       |
| Alur               | Buka Tagihan → tampilkan transaksi belum lunas → pilih Detail → ambil transaksi + item + pembayaran aktif → lihat histori pembayaran → jika masih ada sisa, pengguna berwenang dapat melakukan pelunasan/backdate → setelah lunas transaksi tidak lagi memenuhi query daftar Tagihan.                                                    |
| Hak Akses          | Membutuhkan login. Aksi pembayaran mengikuti kewenangan pembayaran; backdate membutuhkan admin atau Effective Shift Leader.                                                                                                                                                                                                              |
| Kondisi & Batasan  | `batal` dan `mangkrak` tidak masuk Tagihan. Transaksi `selesai + belum_bayar/dp` tetap dapat menjadi tagihan. Transaksi `selesai + lunas` tidak menjadi tagihan. Tidak ada mekanisme jatuh tempo individual yang tersimpan di database.                                                                                                  |
| Data yang Terlibat | `transaksi`, `pembayaran`, `detail_transaksi`, `pelanggan`, `users`, `KalkulasiStatusPembayaran`, dan `KalkulasiJatuhTempo`.                                                                                                                                                                                                             |
| Catatan            | Prinsip utama modul ini: **Tagihan ditentukan berdasarkan status pembayaran, bukan status transaksi**. Archive transaksi juga tidak memiliki fallback pada `Tagihan::detail()`, sehingga detail Tagihan bergantung pada database transaksi utama.                                                                                        |
