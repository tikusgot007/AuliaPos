# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-yellow)

Rincian eksekusi **sisi AuliaPos** untuk `spec/spec-design-balas-pesan.md` (v1.5, GH-015): kasir dapat menunjuk satu pesan (teks/media) lalu membalasnya dengan **kutipan native WhatsApp**, serta penerimaan **kutipan pada pesan MASUK** dari pelanggan. Balas Pesan menyentuh **dua repo**, sehingga menghasilkan **dua plan terpisah** (PRD Section 9.1; `spec/spec-index.md` "Urutan Pengerjaan Wajib"): plan ini untuk AuliaPos, dan `plan/plan-feature-balas-pesan-wa-gateway-v1.0.md` untuk `tikusgot007/WA-Gateway`. > [!NOTE]
> **Catatan revisi plan (2026-09-27, diterapkan tanpa ubah requirement):** menindaklanjuti `docs/audit/clarification-report-balas-pesan-plans-v1.4-2026-09-27.md` (Iteration 2, 89/100, PROCEED) dan spec **v1.5**. Perubahan additive pada task, **tanpa** mengubah `AC`/`REQ`: **F-A** guard intra-percakapan `400` (TASK-002/006), **F-D** taksonomi lookup sumber (TASK-002/006), **F-B** diskriminator `quoted_sender_label IS NULL` + fallback `"Pengirim"` (TASK-010/011), beserta test otomatis terkait. Item **F-E** dicatat sebagai `[Assumed]` (`ASSUMPTION-008`/`009`/`010`). Tidak ada requirement baru; `CONTEXT.md`/ADR tidak berubah.

Tanpa itu, `quoted_message_id` akan dikirim ke Gateway lama dan fitur tidak berfungsi. Urutan rollout: **Gateway naik dulu → AuliaPos naik**. Urutan rollback: **Gateway turun dulu**.

## 1. Requirements & Constraints

**Diimplementasikan di plan ini (sisi AuliaPos):**

- **REQ-004**: UI thread pesan menambahkan aksi **Balas** pada setiap bubble (kecuali pesan yang sedang dihapus/gagal kirim), mengikuti pola tombol aksi per-pesan yang sudah ada. Saat ini bubble **belum punya menu aksi sama sekali** (`app/Views/inbox/index.php:1896-1901`, `renderPesan()`).
- **REQ-005**: Memilih **Balas** menampilkan area kutipan aktif di atas kotak ketik (cuplikan teks terpotong / label jenis media + nama pengirim, memakai `sender_jid`/nama kontak; untuk grup memakai label Tahap 2 `SenderIdentityFormatter`), dengan tombol batal untuk melepas pilihan tanpa mengirim.
- **REQ-006 (reaksi (a))**: Jika respons Gateway `quote_applied: false`, AuliaPos **tidak** mengirim ulang otomatis; pesan tetap tersimpan terkirim dan ditandai di UI **"Terkirim tanpa kutipan"**.
- **REQ-006a (reaksi (c))**: Jika request kirim berkutipan berakhir ambigu/timeout tanpa respons definitif, pesan **tidak** ditandai terkirim maupun gagal, dan ditampilkan peringatan **"Hasil belum pasti, jangan kirim ulang dulu"** (pola `gatewayFailureResponse()` `SEND_IN_PROGRESS`/`SEND_UNRESOLVED`, `app/Controllers/Inbox.php:2501-2510`), tanpa pengiriman ulang otomatis.
- **REQ-007**: Kutipan disimpan sebagai kolom baru pada baris pesan balasan itu sendiri (snapshot saat itu, tidak pernah di-refresh dari pesan asli).
- **REQ-008**: `quoted_media_available` mengikuti aturan spec: `0` **hanya** bila `media_local_filename` sumber kosong **DAN** `media_confirmed_gone_at` terisi; `1` = heuristik (media-typed, belum confirmed-gone → potentially available); `NULL` = sumber bukan media **ATAU** ketersediaan belum/tidak teresolusi. Saat bernilai `0` **atau** saat permintaan media sumber saat tampilan mengembalikan `404`/`410`/error, UI menampilkan **"[Media tidak tersedia]"** (persis) **tanpa** menulis ulang DB — snapshot tetap beku (spec REQ-007/REQ-008/AC-005).
- **REQ-009**: Pengiriman balasan memakai **ulang** mekanisme idempotensi `operation_id`/`gateway_operation_id` yang sudah ada (`findMessageByOperationId()`, `app/Controllers/Inbox.php:2292`).
- **CON-002 (reaksi (b))**: Kegagalan HTTP total saat mengirim berkutipan berperilaku **sama seperti kegagalan kirim pesan biasa** — pesan ditandai gagal, kasir bisa coba lagi (tidak ada penanganan khusus tambahan).
- **GUD-001**: Kolom kutipan baru **nullable**, additive; baris non-balasan tetap `quoted_* = NULL`.
- **REQ-001a (pemakaian jalur media)**: Balas-dengan-media-sambil-mengutip memakai `POST /send-media` dengan field `quoted` (kontrak Gateway) — pesan media tersimpan dengan `quoted_*` terisi sama seperti balasan teks.
- **REQ-010**: `POST /api/inbox/gateway/messages` (`InboxGatewayApi::messages()`) menerima field opsional `quoted` pada payload pesan **masuk** (`quoted.wa_message_id` wajib jika objek ada, `quoted.sender_jid` opsional, `quoted.snippet` opsional).
- **REQ-011**: `InboxGatewayApi::messages()` mencari `quoted.wa_message_id` di tabel `messages` milik AuliaPos sendiri **sebelum** mengisi kolom kutipan — lookup **wajib menyertakan baris soft-deleted** (`withDeleted()`/query tanpa filter `deleted_at`; `MessageModel::find()`/`first()` polos **dilarang**, spec REQ-011/Section 12):
  - **Ditemukan** → isi `quoted_wa_message_id`, `quoted_sender_label`, `quoted_snippet`, `quoted_media_available` dari **data lokal** (bukan `quoted.snippet` payload).
  - **Tidak ditemukan** → `quoted_wa_message_id` tetap diisi, `quoted_snippet` dari `quoted.snippet` payload apa adanya (atau label generik **"Pesan tidak ditemukan"** bila kosong), `quoted_media_available = NULL`; penyimpanan pesan masuk **tidak** digagalkan.
- **REQ-012**: Lookup REQ-011 hanya dijalankan **saat `quoted` ada** di payload (kondisional), tidak menambah query pada jalur normal.
- **REQ-013**: Kotak kutipan tampil pada bubble pesan **masuk** yang punya `quoted_wa_message_id`, memakai komponen tampilan **sama** dengan kutipan balasan kasir, termasuk placeholder **"[Media tidak tersedia]"** dan label **"Pesan tidak ditemukan"**. Tidak ada komponen UI baru.

**Di luar plan ini (milik plan WA-Gateway):** `REQ-001`, `REQ-001a`, `REQ-002`, `REQ-003`, `CON-001` (sisi kirim Gateway), dan ekstraksi `quoted` arah masuk dari Baileys `contextInfo`.

**Acceptance Criteria yang dipetakan (spec Section 5):** `AC-001`, `AC-002` (uji manual native), `AC-003`, `AC-003a`, `AC-003b`, `AC-004`, `AC-005`, `AC-006`, `AC-007`, `AC-008`, `AC-009`.

## 3. Alternatives

- **ALT-001**: Menyimpan kutipan sebagai foreign key hidup ke `messages.id` — **ditolak** (`REQ-007`, spec Section 9 "Never do"): kutipan harus snapshot yang tidak berubah saat pesan asli diubah/di-soft-delete.
- **ALT-002**: Mengambil data pesan asli dari client (payload browser) saat membalas — **ditolak** (spec Section 9 "Always do" pada Teruskan, prinsip sama): server harus mengambil dari DB sendiri untuk mencegah manipulasi.
- **ALT-003**: Membuat komponen UI kutipan terpisah untuk pesan masuk dan pesan keluar — **ditolak** (`REQ-013`): satu komponen yang sama dipakai dua arah.

## 7. Risks & Assumptions

- **ASSUMPTION-004 (dari spec, HIGH RISK)**: Baileys mendukung reply native lewat opsi `quoted` pada `sendMessage()`. **Belum** diimplementasikan di Gateway. Task `TASK-002`/`TASK-006` bergantung pada ini; mitigasi = fallback didefinisikan di plan Gateway (`CON-001` Gateway: pesan tetap terkirim walau kutipan gagal).
- **ASSUMPTION-006 (dari spec)**: kolom `quoted_*` yang sama dipakai ulang untuk kutipan **masuk** (bukan 4 kolom baru). Task terkait: `TASK-010`.
- **ASSUMPTION-007 (dari spec)**: AuliaPos mencoba resolve `quoted.wa_message_id` ke DB lokal dulu, fallback ke snippet payload Gateway. Task terkait: `TASK-010`.
- **ASSUMPTION-001 (rencana)**: `quoted_sender_label` untuk kutipan dibangun dari seam identitas yang sudah ada (`SenderIdentityFormatter` + `UserModel`); tidak ada format label baru yang diminta spec.
- **ASSUMPTION-008 [Assumed] (F-E / F4 — marker ephemeral)**: penanda **"Terkirim tanpa kutipan"** hanya tampil pada bubble hasil respons saat itu dan **tidak** bertahan setelah reload/polling thread (ephemeral); `AC-003` terpenuhi pada waktu pemrosesan respons; tidak ada kolom baru (menghormati `GUD-001`).
- **ASSUMPTION-009 [Assumed] (F-E / F7 — pemotongan snippet)**: snippet kutipan dipotong dengan `mb_substr($text, 0, 200)` dan menambahkan `…` **hanya** bila benar-benar terpotong (multibyte-safe, selaras "mis. 200 karakter" spec).
- **ASSUMPTION-010 [Assumed] (F-E / F8 — `quote_applied` hilang)**: bila Gateway mengembalikan `sent:true` tetapi **tidak** menyertakan `quote_applied` (rollout parsial), AuliaPos memperlakukannya sebagai **`false`** dan menampilkan "Terkirim tanpa kutipan"; gate rilis `TASK-015`/`EXT-001` menjaga keadaan ini transien.
- **RISK-001 (operasional, tinggi)**: Merilis AuliaPos sebelum Gateway baru → `quoted` diabaikan Gateway lama; fitur tidak berfungsi. Mitigasi: gate rilis `TASK-015`.
- **RISK-002 (celah spec, teridentifikasi)**: Spec `Section 7` tidak mendaftarkan pekerjaan ekstraksi `quoted` arah masuk di Gateway, padahal `REQ-010` menuntutnya. Mitigasi: `TASK-003` di plan Gateway; dicatat untuk `/sdlc-audit-consistency`.
- **RISK-003 (drift penamaan)**: Spec menyebut rute `POST /inbox/percakapan/{id}/kirim` yang tidak ada di kode; plan memakai rute aktual `POST /inbox/kirim`. Tidak mengubah perilaku.
- **Tidak ada ADR baru; `CONTEXT.md` tidak berubah** (spec Section 10).

## 9. Rollback / Recovery Plan

Urutan rollback = **Gateway turun dulu**, baru AuliaPos (kebalikan urutan rilis).

1. **Gateway turun dulu**: kembalikan repo `tikusgot007/WA-Gateway` ke versi sebelum plan Gateway. Selama jendela ini, Gateway lama mengabaikan field `quoted` yang dikirim AuliaPos → pesan tetap terkirim **tanpa kutipan** (tidak hilang, tidak error).
2. **AuliaPos turun**: `git revert` commit plan ini untuk `app/Controllers/Inbox.php`, `app/Controllers/InboxGatewayApi.php`, `app/Models/MessageModel.php`, dan `app/Views/inbox/index.php`.
3. **Migrasi**: jalankan `php spark migrate:rollback` untuk menghapus 4 kolom `quoted_*` **hanya bila** perlu — snapshot kutipan yang sudah tersimpan akan hilang. Bila kolom dibiarkan (nullable, additive), tidak ada risiko dan tidak ada backfill mundur.
4. Tidak ada environment variable yang perlu direstorasi.
5. Jalankan `vendor/bin/phpunit --no-coverage` untuk memastikan kembali hijau setelah rollback.
