# Introduction

![Status: Completed](https://img.shields.io/badge/status-Completed-brightgreen)

Rincian eksekusi **sisi AuliaPos** untuk `spec/spec-design-grup-tahap2-identitas.md` (v1.3, Readiness 90/100): menampilkan **identitas pengirim** tiap pesan grup, dan **nama grup asli** sebagai judul percakapan yang stabil. Tahap 2 menyentuh **dua repo**, sehingga menghasilkan **dua plan terpisah** (PRD Section 9.1; `spec-index.md` "Urutan Pengerjaan Wajib"): plan ini untuk AuliaPos, dan `plan-feature-grup-tahap2-wa-gateway-v1.0.md` untuk `tikusgot007/WA-Gateway`. Prasyarat: **Tahap 1 sudah rilis** (`plan/plan-feature-grup-tahap1-v1.0.md`).

> [!IMPORTANT]
> **Constraint urutan rilis (`CON-004`/`EXT-001`) — non-negotiable.** Plan AuliaPos ini **hanya boleh dirilis setelah** perubahan kontrak Gateway (plan Gateway) terpasang di toko. Gateway lama tidak mengirim `sender_jid`, sehingga **setiap** pesan grup ditolak `400` dan **tidak tersimpan** (`REQ-010`) — bukan disimpan sebagian, bukan masuk antrean (proyek ini **tidak punya outgoing queue**, `docs/CHAT.md` §5/§18; retry adalah aksi manusia). Urutan rollout: **Gateway naik dulu → AuliaPos naik**. Urutan rollback: **Gateway turun dulu**.

## 1. Requirements & Constraints

**Diimplementasikan di plan ini (sisi AuliaPos):**

- **REQ-004**: `messages.sender_jid` **sudah** ditulis tanpa syarat di `app/Controllers/InboxGatewayApi.php:251` dan **sudah** ada di `MessageModel::$allowedFields` (`app/Models/MessageModel.php:46`). Tidak ada baris penyimpanan baru; sisa pekerjaan = validasi (`REQ-010`) + tampilan (`REQ-008`).
- **REQ-005**: `payload['group_name']` disimpan ke kolom baru `conversations.group_name`, hanya kalau field ada DAN conversation belum punya `group_name` — berlaku pada **kedua jalur**: conversation lama (update) dan conversation yang **baru dibuat dalam request yang sama** (`resolveConversationId()` → `created=true`, `app/Models/ConversationModel.php:394-413`). Pada jalur `created=true`, `group_name` ditulis pada baris yang baru dibuat di request itu (tidak ditunda ke pesan berikutnya).
- **REQ-006 (write-once)**: `group_name` hanya ditulis kalau kolom itu masih `NULL` (`=== null`, bukan `empty()`). Setelah terisi, nilai berikutnya (termasuk nama berbeda) **tidak menimpa**. Dua penulisan pertama yang benar-benar bersamaan berakhir *last-write-wins* — **diterima** (kasus jarang, sumber nilai sama, tidak ada kode baru pencegahnya).
- **REQ-007**: Judul percakapan grup di UI menampilkan `conversations.group_name` kalau terisi; kalau `NULL` → teks generik **"Grup"**. **Tidak pernah** memakai `whatsapp_name`/identitas pengirim terakhir sebagai fallback — hanya untuk kondisi `jid_type === 'group'`; perilaku pribadi tidak berubah.
- **REQ-008**: Setiap pesan grup **incoming** menampilkan identitas pengirim dari `messages.sender_jid`: **nomor telepon** untuk `@s.whatsapp.net`, penanda generik **`LID`** untuk `@lid` (mengikuti pola `jid_type === 'lid' ? 'LID' : ...`, `app/Views/inbox/index.php:1144`). Nama orang per peserta **bukan** bagian kontrak (Keputusan A).
- **REQ-009**: Pesan grup outgoing menampilkan nama staff pengirim (`sent_by_user_id` → `UserModel`); outgoing sinkron WA Web/HP (`sent_by_user_id = NULL`) menampilkan **"Staff (WA Web/HP)"**. `messages.sender_jid` untuk outgoing (dibuat AuliaPos) tetap `NULL` — perilaku sekarang tidak berubah.
- **REQ-010**: `InboxGatewayApi::messages()` menolak `400` kalau `jid_type === 'group'` dan `sender_jid` kosong/absen, dan **tidak menyimpan apa pun** (tanpa baris `messages`, tanpa perubahan `conversations`, termasuk `group_name` tidak ditulis). Validasi dijalankan **sebelum** transaksi insert. Tidak mengubah perilaku `jid_type` selain `'group'`.
- **CON-001**: `sender_jid`/`group_name` **tidak pernah** diproses untuk `jid_type` selain `'group'` (penegakan sisi AuliaPos: hanya perbarui `group_name` saat `jid_type === 'group'`; `sender_jid` dari payload non-grup tetap ditulis apa adanya seperti sekarang — `InboxGatewayApi.php:251` tanpa syarat, tidak diubah).
- **CON-002**: `conversations.group_name` = kolom **baru** `VARCHAR(255) NULL` (satu-satunya perubahan skema di seluruh PRD). **Tidak** memakai ulang `whatsapp_name`/`contact_name`.
- **CON-003**: Pesan grup lama (`messages.sender_jid IS NULL`) ditampilkan **tanpa** baris label pengirim (bukan `"?"`/teks kosong membingungkan).
- **CON-004 (urutan rilis)**: lihat Introduction; berlaku untuk seluruh plan AuliaPos ini.
- **GUD-002**: `group_name` di payload **additive** — Gateway lama tanpa field ini tidak boleh membuat AuliaPos error (`payload['group_name'] ?? null`).
- **AC-009 (lingkup arah — keputusan pemilik, 2026-09-26)**: guard `400` diberlakukan untuk pesan grup **incoming saja** (`direction === 'incoming'`). Pesan grup outgoing sinkron WA Web/HP dengan `sender_jid` NULL **tetap diterima** (dibutuhkan oleh `AC-011`). Ini mempersempit frasa literal `AC-009` "request `jid_type='group'` tanpa `sender_jid`" sebesar satu kondisi arah; asersi uji `AC-009` (grup incoming tanpa `sender_jid` → `400` + tidak tersimpan) tetap terpenuhi persis.

- **ASSUMPTION-004 (lintas-repo, arah)**: WA-Gateway **selalu** mengirim `direction` yang benar untuk setiap pesan grup (`fromMe` → `'outgoing'`, selain itu → `'incoming'`). Ini dependency keras terhadap plan WA-Gateway (`TASK-001`/`TASK-003`): karena `direction` default `'incoming'` bila absen (`InboxGatewayApi.php:71`), pesan grup `fromMe` tanpa `direction` akan salah-anggap incoming, kena guard `400`, dan **hilang permanen** — kegagalan yang `CON-004` ada untuk mencegahnya.

**Di luar plan ini (milik plan WA-Gateway):** `REQ-001`, `REQ-002`, `REQ-003`, `CON-001` (sisi kirim Gateway), `GUD-001`.

## 3. Alternatives

- **ALT-001**: Memakai ulang `conversations.whatsapp_name` untuk nama grup — ditolak (`CON-002`): `whatsapp_name` adalah identitas kontak perorangan yang selalu ditimpa otomatis, melanggar invarian "setiap operasi hanya menulis kolom yang jadi tanggung jawabnya" (`docs/CHAT.md` §18). `group_name` terpisah justru penerapan invarian itu, bukan trade-off baru — karena itu tidak butuh ADR (spec Section 10, gagal *Triple Gate Validation*).
- **ALT-002**: Menampilkan **nama orang** per peserta (sinkronisasi kontak) — ditolak (Keputusan A, `REQ-008`): Baileys tidak menjamin nama tersedia tanpa sinkronisasi kontak; kontrak hanya nomor telepon atau `LID`.
- **ALT-003**: Menambah endpoint/panggilan baru untuk mengambil nama grup saat render — ditolak (PRD Section 8.3; `ASSUMPTION-003`): nilai disimpan per baris conversation dan ikut termuat bersama thread/daftar yang sudah ada, tanpa permintaan per pesan.

## 7. Risks & Assumptions

- **ASSUMPTION-002** *(dari spec)*: Baileys menyediakan `key.participant` untuk pesan grup masuk dan `groupMetadata(jid).subject` untuk nama grup. Ini **ditambah** di WA-Gateway (bukan mengaktifkan yang sudah ada) — konsekuensi untuk plan Gateway, bukan blocker plan AuliaPos.
- **ASSUMPTION-003** *(dari spec)*: `groupMetadata()` di-cache per JID grup (bukan panggilan jaringan tiap pesan); implementasi caching sepenuhnya wewenang plan Gateway (`GUD-001`).
- **ASSUMPTION-004 (lintas-repo, arah)**: WA-Gateway selalu mengirim `direction` yang benar untuk setiap pesan grup (`fromMe` → `'outgoing'`, selain itu → `'incoming'`); di-assert di plan Gateway (`TASK-003` f). Tanpa jaminan ini, pesan grup `fromMe` tanpa `direction` default ke `'incoming'` (`InboxGatewayApi.php:71`), kena guard `400`, dan hilang permanen — karena itu dependency ini blocking (`DEP-001`).
- **RISK-001 (operasional, tinggi)**: Bila AuliaPos dirilis sebelum Gateway terpasang, **semua** pesan grup ditolak `400` dan hilang (tanpa antrean). Mitigasi: gate `CON-004` di TASK-008; jangan tutup TASK-009 sebelum bukti Gateway naik.
- **RISK-002 (RESOLVED, keputusan pemilik 2026-09-26)**: Lingkup guard `400` = pesan grup **incoming** saja. Outgoing sinkron WA Web/HP tetap diterima (`sender_jid` NULL) agar `AC-011` dapat tersimpan.
- **RISK-003 (diterima)**: Dua penulisan `group_name` pertama yang bersamaan → *last-write-wins*; kedua nilai berasal dari subject grup yang sama; tidak ada kode pencegah (spec `REQ-006`).
- **Tidak ada ADR baru; `CONTEXT.md` tidak berubah** (spec Section 10).

## 9. Rollback / Recovery Plan

Per `CON-004`, urutan rollback = **Gateway turun dulu**, baru AuliaPos.

1. **Gateway turun dulu**: kembalikan repo `tikusgot007/WA-Gateway` ke versi sebelum plan Gateway (lihat Section 9 plan Gateway). Selama jendela ini, Gateway lama + AuliaPos baru → pesan grup ditolak `400` dan tidak tersimpan; **minimalkan durasi jendela** dan lakukan pada jam sepi.
2. **AuliaPos turun**: `git revert` commit plan ini untuk `app/Controllers/InboxGatewayApi.php`, `app/Controllers/Inbox.php`, `app/Views/inbox/index.php`, dan `app/Models/ConversationModel.php`.
3. **Migrasi**: jalankan `php spark migrate:rollback` untuk menghapus kolom `conversations.group_name` **hanya bila** benar-benar perlu — nilai `group_name` yang sudah tersimpan akan hilang. Bila kolom dibiarkan (nullable, additive), tidak ada risiko; tidak ada backfill/migrasi data mundur (PRD Section 8.2).
4. Tidak ada environment variable yang perlu direstorasi.
5. Jalankan `vendor/bin/phpunit --no-coverage` untuk memastikan kembali hijau setelah rollback.
